============================================================
0. MISSION
============================================================

Implémente la PHASE 8 complète de UNI-PAY.

Objectif :

Transformer un lot de paie officiellement AUTHORIZED en processus de paiement contrôlé permettant :

AUTHORIZED
→ validation pré-paiement
→ création PaymentOrder
→ préparation du paiement
→ PAYMENT_PROCESSING
→ génération d'un fichier technique générique
→ confirmation contrôlée
→ rapprochement
→ PAID
→ CLOSED

IMPORTANT :

Cette Phase 8 est une simulation/gestion institutionnelle de paiement et de fichiers techniques.

UNI-PAY NE DOIT PAS prétendre être connecté à une banque.

NE PAS implémenter :

- API bancaire réelle
- CIB
- Edahabia
- SATIM
- SWIFT réel
- API bancaire
- connexion directe à une banque
- paiement automatique réel
- transfert bancaire réel

Le fichier généré doit être explicitement présenté comme :

"Export technique générique UNI-PAY — non présenté comme format bancaire officiel."

5. CONDITIONS POUR AUTHORIZED → PAYMENT_PROCESSING
============================================================

AVANT de permettre START_PAYMENT_PROCESSING :

exécuter obligatoirement une validation serveur complète.

Créer :

lib/payment/payment-validation.ts

Le contrôle doit vérifier :

1. batch existe ;
2. batch appartient à l'organisation de l'utilisateur ;
3. batch.status === AUTHORIZED ;
4. batch possède des PayrollRecords ;
5. nombre d'employés > 0 ;
6. chaque PayrollRecord correspond à un Employee valide ;
7. chaque Employee possède un RIB non vide ;
8. le RIB respecte la validation structurelle définie par le projet ;
9. aucune anomalie de RIB dans le même lot ;
10. aucun doublon de RIB dans le lot ;
11. chaque montant net est valide ;
12. aucun montant négatif ou incohérent ;
13. total batch = somme exacte des PayrollRecord.netAmount ;
14. total > 0 ;
15. aucun PayrollRecord manquant ;
16. aucune incohérence Employee ↔ PayrollRecord ;
17. aucune version intermédiaire ou rejetée ne doit être utilisée.

IMPORTANT :

Le système peut vérifier la structure et la cohérence du RIB.

Il NE DOIT PAS prétendre vérifier qu'un compte bancaire est réellement actif sans intégration bancaire.
